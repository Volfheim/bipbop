# 🐺 Volfheim VPN (BipBop)

**Volfheim VPN** — это высокопроизводительное VPN-решение для Android, построенное по принципу «слоеного пирога». Здесь каждый уровень изолирован и выполняет свою специфическую задачу для обеспечения максимальной скорости и бесшовного роуминга.

---

## 🍰 Архитектура проекта

Проект разделен на 5 технологических уровней:

### 1. Уровень Интерфейса (Flutter / Dart)
- **Фреймворк**: Flutter
- **Задача**: Сбор Smart-Key, управление состоянием ("Подключено"/"Ошибка"), визуализация "живых" логов.
- **Связь**: Общается с системным слоем через `MethodChannel` (`com.volfheim.bipbop/vpn`).

### 2. Уровень Системы (Kotlin / Android VpnService)
- **Сердце**: `BipBopVpnService`
- **Роуминг (Handover)**: Реализован нативный механизм адаптации под смену Wi-Fi/LTE.
- **Туннелирование**: Создает виртуальный интерфейс (обычно `tun0`) и передает его файловый дескриптор в Go-ядро.
- **Split Tunneling**: Автоматический обход (Bypass) для 33+ публичных префиксов (банки, государственные сервисы).

### 3. Уровень Моста (JNI / CGO)
- **Асинхронность**: Запуск VPN происходит в фоновом потоке, не блокируя UI.
- **Стабильность**: Использование `AttachCurrentThreadAsDaemon` и глобальных ссылок (GlobalRefs) для предотвращения крашей при сборке мусора (GC).

### 4. Уровень Ядра (Go Engine)
- **Протокол**: KCP (UDP) + Yamux (Stream Multiplexing).
- **ICE & TURN**: Автоматическое согласование через TURN-серверы Wildberries.
- **Smart Continuity**: Алгоритм "терпеливого прокси", который удерживает соединения браузера до 5 секунд во время переподключения сессии.

### 5. Уровень Перехватчика (tun2socks)
- **DNS Protection**: Семафор на 200 одновременных запросов для защиты от переполнения памяти (OOM).
- **VoIP Support**: Реализация `UDP Associate` для стабильных звонков в Telegram/WhatsApp.

## 🛠 Технические особенности раздачи интернета (Tethering)

Если вы используете Magisk-модули для раздачи интернета через VPN:
1. **Интерфейс**: Android обычно назначает имя `tun0`. Имя может динамически меняться на `tun1`, если была активна прошлая сессия.
2. **Проблема Magisk**: Наше ядро работает через `tun2socks` (Userspace Proxy). Это перехватывает трафик в Go, поэтому классический NAT в ядре Linux может "не видеть" пакеты.
3. **Рекомендация**: Используйте модули, поддерживающие перенаправление трафика горячей точки на SOCKS5-прокси. 
   - **Адрес прокси**: `127.0.0.1:13349`.
   - **Интерфейс для мониторинга**: `tun+` (маска любая `tunX`).

## 🚀 Сборка проекта

1. **Ядро**: `cd bipbop-engine/mobile/android/golib && ./build.sh` (требуется Go 1.25+ и NDK 28).
2. **Приложение**: `cd bipbop-android && flutter build apk --release`.
